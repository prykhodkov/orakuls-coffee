# Orākuls Coffee — контракт API

Версія: 0.2 (2026-11-03) — F-001…F-005, B-001, B-002: типи в JSON, ліміт входу й токен, межі параметрів, другий формат файлу імпорту, статистика відвідувань (`POST /api/visit`, `GET /api/admin/visits`), без ліміту посланнь.
Попередня: 0.1 (чернетка, 2026-10-26).

Фронтенд (сторінка користувача + адмінка) — папка `frontend/`. Бекенд — папка `backend/`.
Цей документ — єдине джерело правди про взаємодію між ними. Будь-які зміни — спочатку тут.

## Загальне

- Базова адреса: `/api` (фронт і API на одному домені, див. розділ «Розгортання»).
- Формат: JSON, `Content-Type: application/json; charset=utf-8`.
- Дати: ISO 8601 в UTC, напр. `"2026-10-26T18:30:00Z"`.
- Ідентифікатори: цілі числа.
- **Типи (F-003).** Усі числа (`id`, `total`, `page`, лічильники…) — JSON-числа, не рядки. `isActive` — `true`/`false`, не `1`/`0`. Об'єкти (`text`, `byCategory`, `missing`, `byLang`, `fields`) — завжди `{}`, навіть порожні, а не `[]`.
- **Тіло запиту.** Порожнє, не JSON або не JSON-об'єкт (число, рядок, непорожній список) → `400 bad_request`.

### Довідники (фіксовані значення)

**Мови** (`lang`):

| Код  | Мова       |
|------|------------|
| `lv` | Latviešu   |
| `en` | English    |
| `ru` | Русский    |

**Категорії** (`category`):

| Код       | Назва               |
|-----------|---------------------|
| `love`    | ❤️ Любов            |
| `money`   | 💰 Гроші            |
| `luck`    | 🍀 Удача            |
| `work`    | 💼 Робота           |
| `travel`  | ✈️ Подорожі         |
| `mood`    | ☀️ День / Настрій   |

Назви категорій і мов на всіх мовах інтерфейсу зберігає фронт — бекенд оперує лише кодами.

### Формат помилок

Усі помилки (4xx, 5xx) повертають однакову структуру:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Людиночитаний опис",
    "fields": { "text.lv": "too_long" }
  }
}
```

`fields` — лише для `validation_error`, ключі — шлях до поля в тілі запиту.

| HTTP | `code`              | Коли                                      |
|------|---------------------|-------------------------------------------|
| 400  | `bad_request`       | Некоректний JSON / параметри запиту        |
| 401  | `unauthorized`      | Немає токена, токен прострочений/невалідний|
| 404  | `not_found`         | Сутність не знайдена                       |
| 422  | `validation_error`  | Не пройшла валідація полів                 |
| 429  | `rate_limited`      | Забагато спроб входу (див. «Авторизація»)  |
| 500  | `server_error`      | Внутрішня помилка                          |

## Публічна частина

### `GET /api/message` — отримати випадкове послання

Без авторизації. Викликається, коли користувач натискає «Отримати моє послання».

**Query-параметри:**

| Параметр   | Обов'язковий | Опис |
|------------|--------------|------|
| `lang`     | так          | `lv` \| `en` \| `ru` — мова, яку користувач обрав на першому екрані. Лише нижній регістр без пробілів (`LV`, `lv `, `lang[]=lv` → `400`) |
| `exclude`  | ні           | ID фраз через кому, які користувач уже бачив (фронт зберігає останні 100 у localStorage, тож до ~500 символів). Бекенд намагається їх уникнути; якщо після виключення нічого не лишилось — ігнорує `exclude`. Це підказка: **ніколи** не дає `400`; береться до 200 коректних ID (до 10 цифр), сміття пропускається |

**Логіка вибору:** рівномірно випадкова фраза з усіх категорій серед тих, у яких `isActive = true` і непорожній текст мовою `lang`. Випадковість — на бекенді, фронт ніколи не отримує всю базу. Категорії користувач не бачить — вони лише для організації фраз в адмінці.

**Відповідь 200:**

```json
{
  "id": 42,
  "lang": "lv",
  "text": "Šodien veiksme būs tavā pusē."
}
```

**Помилки:** `400` — невідомий `lang`; `404` — немає жодної доступної фрази.

**Кешування:** `Cache-Control: no-store`.

**Ліміт (F-002):** немає — людина може отримати кілька посланнь на день. Повтори обмежує фронт: повторне відкриття протягом 20 хв показує те саме послання з localStorage без запиту, а ID останніх 100 показаних фраз ідуть у `exclude`.

**Статистика (F-005):** кожна відповідь `200` рахується бекендом як видане послання (`messages`, `byLang[lang]`) за сьогоднішній день за Europe/Riga. `400`/`404` не рахуються. Збій запису лічильника не ламає видачу (лише запис у лог). Фронт нічого додатково не шле.

### `POST /api/visit` — відкриття сайту (F-005)

Без авторизації. Фронт викликає один раз при кожному відкритті сторінки користувача (до вибору мови), `fetch` з `keepalive: true`, відповідь не читає, помилки ігнорує.

**Тіло:** `{ "source": "qr" }` або `{ "source": "direct" }`.

Відкриття з QR на стаканчику: QR веде на `https://orakulscoffee.com/?qr`; фронт бачить параметр `qr`, шле `source: "qr"` і прибирає `?qr` з адреси.

| Ситуація | Відповідь |
|----------|-----------|
| Нормальний запит | `204` без тіла, `Cache-Control: no-store`; `visits += 1`, при `source = "qr"` ще й `scans += 1` |
| `source` відсутній, `null`, невідомий рядок (у т. ч. `"QR"`), не рядок | рахується як `direct`, `204` |
| Тіло порожнє / не JSON / не об'єкт | `400 bad_request`, нічого не рахується (`[]` PHP не відрізняє від `{}` → `204` як `direct`) |
| Помилка БД | `500 server_error` |

Лічильник — лише агреговані кількості по днях; IP, User-Agent, cookies не зберігаються. Ліміту за IP немає.

## Адмінка

Усі ендпоінти `/api/admin/*`, крім логіну, вимагають заголовок:

```
Authorization: Bearer <token>
```

Схема `Bearer` нечутлива до регістру, між схемою і токеном рівно один пробіл. Будь-який запит до `/api/admin/*` без дійсного токена (навіть невідомий шлях чи погані параметри) → `401`, а не `404`/`400`.

На `401` фронт видаляє токен і показує форму входу.

### Авторизація

Адмін **один**, без ролей і керування користувачами. Логін і пароль задаються в конфігурації бекенду (змінні оточення або сід) — ендпоінтів для створення/зміни акаунта немає.

#### `POST /api/admin/auth/login`

```json
{ "login": "admin", "password": "secret" }
```

**200:**

```json
{ "token": "eyJhbGciOi...", "expiresAt": "2026-10-27T18:30:00Z" }
```

**401** — невірний логін/пароль (повідомлення без уточнення, що саме невірне).

**429 `rate_limited`** — 5 невдалих входів з однієї IP за 15 хв; заголовок `Retry-After` (секунди). Успішний вхід лічильник не скидає й не рахується.

Токен — stateless JWT HS256, термін 7 діб (`expiresAt` — ISO 8601 UTC). Фронт його не розбирає. `logout` і оновлення токена немає: фронт просто забуває токен. Зміна пароля або секрету на сервері анулює всі токени.

#### `GET /api/admin/auth/me`

Перевірка, що токен ще дійсний (при відкритті адмінки).

**200:** `{ "login": "admin" }`

### Сутність `Phrase`

Одна фраза = один запис з трьома перекладами.

```json
{
  "id": 42,
  "category": "luck",
  "text": {
    "lv": "Šodien veiksme būs tavā pusē.",
    "en": "Luck is on your side today.",
    "ru": "Сегодня удача на твоей стороне."
  },
  "isActive": true,
  "createdAt": "2026-10-26T18:30:00Z",
  "updatedAt": "2026-10-26T18:30:00Z"
}
```

**Валідація:**

- `category` — обов'язкове, одне з кодів категорій.
- `text` — об'єкт з ключами `lv`, `en`, `ru`. Кожне значення — рядок, можна порожній (переклад ще не готовий), після trim — до **500** символів. Хоча б одна мова має бути непорожньою.
- Фраза без тексту певною мовою просто не потрапляє у видачу `GET /api/message` для цієї мови.
- `isActive` — необов'язкове, за замовчуванням `true`. Дозволяє приховати фразу, не видаляючи.
- Текст зберігається як є (plain text, переноси рядків `\n` дозволені). HTML не інтерпретується — фронт виводить як текст.

### `GET /api/admin/phrases` — список

**Query-параметри (усі необов'язкові):**

| Параметр   | Опис |
|------------|------|
| `category` | Фільтр за кодом категорії |
| `search`   | Пошук підрядка (без урахування регістру й діакритики) по всіх трьох мовах |
| `missing`  | `lv` \| `en` \| `ru` — лише фрази, де переклад цією мовою порожній |
| `isActive` | `true` \| `false` |
| `page`     | Номер сторінки, з 1. За замовчуванням `1` |
| `perPage`  | 1–100, за замовчуванням `50` |

Сортування: `id` за спаданням (нові зверху).

Погані значення `category`, `missing`, `isActive`, `page`, `perPage` → `400 bad_request` (без `fields`). Сторінка за межами діапазону → `200`, `items: []`, правильний `total`. `total` — кількість після фільтрів.

**200:**

```json
{
  "items": [ /* Phrase[] */ ],
  "total": 600,
  "page": 1,
  "perPage": 50
}
```

### `GET /api/admin/phrases/{id}`

**200:** `Phrase`. **404**, якщо немає.

`{id}` тут і в `PUT`/`DELETE` — лише канонічне ціле (`7`, не `007`/`1.5`/`abc`), інакше `404 not_found`.

### `POST /api/admin/phrases` — створити

```json
{
  "category": "love",
  "text": { "lv": "...", "en": "...", "ru": "..." },
  "isActive": true
}
```

**201:** створений `Phrase`. **422** — помилки валідації.

### `PUT /api/admin/phrases/{id}` — оновити

Тіло — як у `POST` (повна заміна полів `category`, `text`, `isActive`). `isActive` не передано → `true`. Ключ мови відсутній або `null` у `text` — порожній переклад, не помилка (так само в `POST`).

**200:** оновлений `Phrase`. **404**, **422**.

### `DELETE /api/admin/phrases/{id}`

**204** без тіла. **404**, якщо немає.

### `POST /api/admin/phrases/import` — масовий імпорт

Адмін завантажує файл CSV або XLSX (Excel). Файл розбирає фронт і відправляє готовий масив.

Фронт приймає два формати файлу:

1. **Таблиця з колонкою `category`** — перший рядок із заголовками, далі по одній фразі на рядок:

   | category | lv  | en  | ru  |
   |----------|-----|-----|-----|
   | love     | ... | ... | ... |

2. **Формат файлу клієнта (F-004)** «Послания на трех языках.xlsx» — без колонки `category`, поділений на розділи: рядок-назва категорії (`❤️ ЛЮБОВЬ — 100`, єдина заповнена клітинка), під ним заголовки `№ | Русский | Latviešu | English`, далі фрази. Категорія береться з назви розділу, повторні заголовки й колонка `№` пропускаються.

Для CSV — UTF-8, роздільник `,` або `;` (визначається автоматично). Лише додавання, існуючі фрази не змінюються, дублікати не відсіюються. Бекенду формат файлу не важливий — він отримує лише масив нижче.

```json
{
  "items": [
    { "category": "love", "text": { "lv": "...", "en": "...", "ru": "..." } },
    { "category": "work", "text": { "lv": "...", "en": "", "ru": "..." } }
  ]
}
```

До 1000 елементів за запит. Валідні елементи зберігаються, невалідні — пропускаються.

**200:**

```json
{
  "created": 598,
  "errors": [
    { "index": 17, "fields": { "category": "invalid" } },
    { "index": 203, "fields": { "text": "empty" } }
  ]
}
```

`index` — позиція в масиві `items` (з 0). `errors` — завжди список, за зростанням `index`; `created + errors.length = items.length`.

Елементи (B-001): `isActive` ігнорується — імпортовані фрази завжди активні. Відсутній ключ мови в `text` або `null` — порожній переклад; `text` без жодної непорожньої мови — `{ "text": "empty" }`. Елемент, що не є об'єктом, — запис у `errors`: `{ "index": i, "fields": { "item": "invalid" } }`.

Некоректний запит (B-001), нічого не зберігається:

| Ситуація | Відповідь |
|----------|-----------|
| Тіло порожнє / не JSON / не об'єкт | `400 bad_request` |
| `items` відсутній | `422`, `fields: { "items": "required" }` |
| `items` не масив (непорожній об'єкт, рядок, число, `null`) | `422`, `fields: { "items": "invalid" }` (порожній `{}` — як `[]`: `200`, `created: 0`) |
| `items` довший за 1000 | `422`, `fields: { "items": "too_many" }` |

**200:**

```json
  "byCategory": {
    "love": 100, "money": 100, "luck": 100,

```

### `GET /api/admin/visits?from=YYYY-MM-DD&to=YYYY-MM-DD` — статистика відвідувань (F-005)

Дати — календарні за часом **Europe/Riga**, обидва кінці включно; обидва параметри обов'язкові.

**200**, `Cache-Control: no-store`:

```json
{
  "from": "2026-10-05",
  "to": "2026-11-03",
  "timezone": "Europe/Riga",
  "total": { "visits": 1600, "scans": 1403, "messages": 1324, "byLang": { "lv": 674, "en": 254, "ru": 396 } },
  "days": [
    { "date": "2026-10-05", "visits": 38, "scans": 33, "messages": 30, "byLang": { "lv": 15, "en": 6, "ru": 9 } }
  ]
}
```

- `visits` — усі відкриття сайту; `scans` — з них із QR; `messages` — видані послання (`= lv + en + ru`). `messages` < `visits` — очікувано.
- `days` — **кожен** день періоду за зростанням дати, дні без даних — нулі.
- `byLang` — завжди `lv`, `en`, `ru`, навіть з нулями. `total` = сума `days` (рахує бекенд).
- Дати в майбутньому дозволені (нулі).

**400 `bad_request`** (без `fields`): `from` або `to` відсутній, порожній, не `YYYY-MM-DD` чи неіснуюча дата (`2026-02-30`, рік `0000`); `from > to`; період довший за **366 днів** включно з кінцями.

## Розгортання

Домен: **`https://orakulscoffee.com`** (без `www`). Фронт і бекенд — на одному домені, CORS не потрібен:

- `/` — сторінка користувача (статика з `frontend/dist/`)
- `/admin/` — адмінка (статика з `frontend/dist/admin/`)
- `/api/*` — бекенд (PHP за правилом `.htaccess`; статика в PHP не йде)

Заголовок `Authorization` має доходити до PHP (правило `E=HTTP_AUTHORIZATION` у `.htaccess`, F-003). Редиректи `http→https` і `www→без www` зберігають query-рядок (`?qr`).

QR на стаканчиках — `https://orakulscoffee.com/?qr` (див. [FRONTEND.md](FRONTEND.md) → «QR-код»).

Службовий `GET /api/health` → `{"status":"ok"}` — поза контрактом, для моніторингу доступності; фронт його не використовує.

Під час розробки фронт проксує `/api` на локальний бекенд — як підключити, див. [FRONTEND.md](FRONTEND.md) → «Робота з локальним бекендом».
