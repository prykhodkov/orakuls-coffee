# Orākuls Coffee — документація

QR-код на стаканчику → користувач обирає мову → отримує випадкове послання.
Фронтенд (`frontend/` — сторінка користувача + адмінка) і бекенд (`backend/`) лежать в одному проєкті, кожну частину веде свій розробник зі своїм Claude-агентом.
Ця папка спільна для обох сторін: вони спілкуються через неї.

## Файли

| Файл | Що всередині | Хто веде |
|------|--------------|----------|
| [API.md](API.md) | Контракт API — єдине джерело правди про взаємодію | Обидва, лише за домовленістю (див. нижче) |
| [FRONTEND.md](FRONTEND.md) | Як влаштований фронт: стек, структура, запуск, рішення | Фронт |

| [FRONT-TO-BACK.md](FRONT-TO-BACK.md) | Запити й питання фронта до бекенда | Фронт пише запити, бекенд відповідає |
| [BACK-TO-FRONT.md](BACK-TO-FRONT.md) | Запити й питання бекенда до фронта | Бекенд пише запити, фронт відповідає |

## Правила обміну

1. **На початку сесії** агент читає файл із запитами до себе (фронт — `BACK-TO-FRONT.md`, бекенд — `FRONT-TO-BACK.md`) і бере в роботу записи зі статусом `open`.
2. **Новий запит** — додається в кінець свого вихідного файлу за шаблоном із цього файлу, з наступним номером (`F-001`, `F-002`… від фронта; `B-001`, `B-002`… від бекенда).
3. **Відповідь** — пишеться під запитом у розділі «Відповідь», статус змінюється. Чужий текст запиту не редагується.
4. **Статуси:**
   - `open` — чекає на іншу сторону;
   - `answered` — інша сторона відповіла, автор запиту має перевірити;
   - `done` — автор запиту підтвердив, що питання закрите;
   - `rejected` — не робимо (з поясненням у відповіді).
5. **Зміни контракту.** `API.md` не змінюється в односторонньому порядку. Спочатку запит в обмінному файлі, після згоди другої сторони — правка в `API.md` з підвищенням версії, і номер запиту згадується в рядку версії.
6. **Рішення клієнта** приймає людина, а не агент. Якщо запит упирається в продуктове питання — агент позначає це у відповіді й лишає статус `open`, доки розробник не уточнить у клієнта.
7. Закриті (`done`/`rejected`) записи не видаляються — це історія рішень.
