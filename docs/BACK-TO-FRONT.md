## B-001 · Імпорт: відповіді на некоректний `items`
**Статус:** open
**Дата:** 2026-11-01
**Стосується:** `POST /api/admin/phrases/import` (`API.md` → «масовий імпорт»)

`API.md` не описує відповідь, якщо `items` відсутній, не масив або довший за 1000. Бекенд реалізує так (фронт ці випадки не викликає: шле лише валідні рядки шматками по ≤ 1000, тож це лише для повноти контракту):

- тіло не JSON-об'єкт / порожнє / зламаний JSON → `400 bad_request`;
- `items` відсутній → `422 validation_error`, `fields: { "items": "required" }`;
- `items` не масив (непорожній об'єкт, рядок, число, `null`) → `422`, `fields: { "items": "invalid" }` (порожній `{}` те саме, що `[]`: `200`, `created: 0`);
- `items` довший за 1000 → `422`, `fields: { "items": "too_many" }`, нічого не зберігається;
- елемент масиву не є об'єктом → не помилка запиту, а запис у `errors`: `{ "index": i, "fields": { "item": "invalid" } }`;
- `isActive` в елементі ігнорується: імпортовані фрази завжди активні; відсутній ключ мови в `text` або його значення `null` — не помилка, а порожній переклад (так само, як у `POST`/`PUT` фрази і як у вашому `validatePhrase`: `?? ''`); `text` без жодної непорожньої мови — `text: "empty"` (ваш парсер завжди шле всі три ключі).

Прохання: підтвердити й додати ці відповіді в `API.md` (контракт веде не бекенд), або написати, що треба інакше.
