## B-001 · Імпорт: відповіді на некоректний `items`
**Статус:** open
**Дата:** 2026-11-01
**Стосується:** `POST /api/admin/phrases/import` (`API.md` → «масовий імпорт»)

`API.md` не описує відповідь, якщо `items` відсутній, не масив або довший за 1000. Бекенд реалізує так (фронт ці випадки не викликає: шле лише валідні рядки шматками по ≤ 1000, тож це лише для повноти контракту):

- тіло не JSON-об'єкт / порожнє / зламаний JSON → `400 bad_request`;
- `items` відсутній → `422 validation_error`, `fields: { "items": "required" }`;
- `items` не масив (непорожній об'єкт, рядок, число, `null`) → `422`, `fields: { "items": "invalid" }` (порожній `{}` те саме, що `[]`: `200`, `created: 0`);
- `items` довший за 1000 → `422`, `fields: { "items": "too_many" }`, нічого не зберігається;
- елемент масиву не є об'єктом → не помилка запиту, а запис у `errors`: `{ "index": i, "fields": { "item": "invalid" } }`;
- `isActive` в елементі ігнорується: імпортовані фрази завжди активні; відсутній ключ мови в `text` або його значення `null` — не помилка, а порожній переклад (так само, як у `POST`/`PUT` фрази і як у вашому `validatePhrase`: `?? ''`); `text` без жодної непорожньої мови — `text: "empty"` (ваш парсер завжди шле всі три ключі).

Прохання: підтвердити й додати ці відповіді в `API.md` (контракт веде не бекенд), або написати, що треба інакше.

## B-002 · Деталі поведінки бекенда, яких немає в `API.md`, — внести при підвищенні версії
**Статус:** open
**Дата:** 2026-11-03
**Стосується:** `API.md` (розділи «Формат помилок», «Авторизація», `GET /api/message`, `GET /api/admin/phrases`, `PUT`)

Під час закриття BE-010 бекенд порівняв реалізацію з `API.md` v0.1. **Суперечностей контракту немає**: усе нижче — уточнення того, що `API.md` або не описує, або лишає «на розсуд бекенду». Фронт ці випадки не викликає (або вже працює з такою поведінкою — перевірено наскрізно в браузері), тож нічого міняти не треба; прохання лише внести в `API.md` разом із підвищенням версії (правило 5), щоб контракт був єдиним джерелом правди. Разом із B-001 (відповіді імпорту на некоректний `items`) і F-005 (`POST /api/visit`, `GET /api/admin/visits`).

| Де | Що реалізовано | У `API.md` зараз |
|----|----------------|------------------|
| Вхід, ліміт спроб | 5 невдалих входів з однієї IP за 15 хв → `429 rate_limited` із заголовком `Retry-After` (секунди); IP — лише `REMOTE_ADDR`; успішний вхід лічильник не скидає й не рахується | «Рекомендовано обмежити (429)» |
| Токен | stateless JWT HS256, термін 7 діб (`expiresAt` — ISO 8601 UTC), `logout` немає — фронт просто забуває токен; зміна пароля анулює всі токени | «Формат токена — на розсуд бекенду» |
| `Authorization` | схема `Bearer` нечутлива до регістру, рівно один пробіл; будь-який `/api/admin/*` без дійсного токена (навіть невідомий шлях чи погані параметри) → `401`, а не `404`/`400` | не уточнено |
| `GET /api/message` | `lang` — лише нижній регістр без пробілів (`LV`, `lv `, `lang[]=lv` → `400`); `exclude` — підказка, **ніколи** не дає `400`: розглядається до 200 коректних ID (до 10 цифр), сміття пропускається | `exclude` описано без меж |
| `GET /api/admin/phrases` | погані значення `category`, `missing`, `isActive`, `page`, `perPage` → `400 bad_request` (без `fields`); сторінка за межами діапазону → `200`, `items: []`, правильний `total`; `total` — кількість після фільтрів; пошук нечутливий до регістру й діакритики | не уточнено |
| `GET /api/admin/phrases/{id}` | `id` — лише канонічне ціле (`7`, не `007`/`1.5`/`abc`); інакше `404 not_found` | не уточнено |
| `PUT` | `isActive` не передано → `true` (повна заміна полів); ключ мови відсутній або `null` у `text` = порожній переклад, не помилка | «повна заміна» без цього правила |
| Тіло запиту | порожнє, не-JSON, не-об'єкт (число, рядок, непорожній список) → `400 bad_request` | `400` згадано загалом |
| Служебне | `GET /api/health` → `{"status":"ok"}` — поза контрактом, для перевірки доступності | немає |
