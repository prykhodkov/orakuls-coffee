# BE-010 · Інтеграція з фронтом і актуалізація документації

| Поле | Значення |
|------|----------|
| Тип | Task |
| Пріоритет | High |
| Компонент | backend, docs |
| Залежить від | BE-003 … BE-009 |

## Опис

Підключити готовий фронт (який зараз працює на моку) до справжнього бекенда, пройти всі сценарії користувача й адмінки наскрізно, виправити розбіжності з контрактом і довести документацію до актуального стану. Фронтовий код не змінюємо — розбіжності оформлюємо запитами в `docs/BACK-TO-FRONT.md`.

## Обсяг

- Запустити фронт із `VITE_API_MOCK=false` та `API_PROXY_TARGET`, що вказує на локальний бекенд; записати інструкцію в `docs/BACKEND.md`.
- Пройти сценарії:
  - користувач: вибір мови → отримання послання (для `lv`, `en`, `ru`), повторне сканування, `exclude`;
  - адмін: вхід, вихід при `401`, список, фільтри, пошук, створення, редагування, приховування, видалення, імпорт CSV/XLSX, головна зі статистикою.
- Автоматизований smoke-скрипт (curl/PHP), що перевіряє ключові ендпоінти за `API.md`, зокрема типи полів.
- Закрити запити `F-001…F-003` (статус `answered` → `done` ставить фронт) і прибрати питання про ліміт з `API.md` разом із підвищенням версії контракту.
- Заповнити `docs/BACKEND.md`: стек, структура, запуск, адреса для `API_PROXY_TARGET`, розгортання, прийняті рішення.

## Acceptance criteria

- [ ] Фронт із `VITE_API_MOCK=false` працює проти локального бекенда без помилок у консолі браузера.
- [ ] Користувацький сценарій: для кожної з мов `lv`, `en`, `ru` кнопка «Отримати моє послання» показує фразу цією мовою; повторні запити з `exclude` не повторюють фрази, доки є інші.
- [ ] Адмінка: вхід з правильним паролем веде на головну; з неправильним — повідомлення про помилку; після завершення терміну токена чи його видалення — повернення на форму входу.
- [ ] Адмінка: створення, редагування, приховування («Показывается» → приховано), видалення фрази працюють і відображаються у списку; кнопки «Изменить»/«Удалить» знаходять фразу за числовим `id`.
- [ ] Адмінка: фільтри за категорією, мовою відсутнього перекладу, активністю та пошук працюють; пагінація показує правильний `total`.
- [ ] Адмінка: імпорт реального CSV (UTF-8, роздільники `,` і `;`) і XLSX із ~600 рядків проходить, звіт про помилки відповідає справжнім проблемним рядкам.
- [ ] Головна адмінки показує статистику, що збігається зі списком.
- [ ] Smoke-скрипт покриває всі ендпоінти з `API.md`, перевіряє типи (числа, boolean, об'єкти) і HTTP-коди з контракту; усі перевірки зелені.
- [ ] Усі розбіжності з контрактом або виправлені в бекенді, або оформлені запитами `B-xxx` у `docs/BACK-TO-FRONT.md`; не лишається неузгоджених відхилень.
- [ ] `docs/BACKEND.md` не містить розділу «Що потрібно заповнити» — усі пункти заповнені.
- [ ] Запити `F-001…F-003` закриті (`done`) фронтом; `API.md` оновлений з номером версії та посиланням на запит у рядку версії.
- [ ] Інтеграцію повторно перевірено на хостингу GoDaddy (BE-009): ті ж сценарії проходять на справжньому домені.
