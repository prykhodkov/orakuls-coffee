# BE-010 · Інтеграція з фронтом і актуалізація документації

| Поле | Значення |
|------|----------|
| Тип | Task |
| Пріоритет | High |
| Статус | **Частково виконано (2026-11-03): код і документація готові, лишились закриття запитів фронтом і повторна перевірка на хостингу** |
| Компонент | backend, docs |
| Залежить від | BE-003 … BE-009 |

## Опис

Підключити готовий фронт (який зараз працює на моку) до справжнього бекенда, пройти всі сценарії користувача й адмінки наскрізно, виправити розбіжності з контрактом і довести документацію до актуального стану. Фронтовий код не змінюємо — розбіжності оформлюємо запитами в `docs/BACK-TO-FRONT.md`.

## Обсяг

- Запустити фронт із `VITE_API_MOCK=false` та `API_PROXY_TARGET`, що вказує на локальний бекенд; записати інструкцію в `docs/BACKEND.md`.
- Пройти сценарії:
  - користувач: вибір мови → отримання послання (для `lv`, `en`, `ru`), повторне сканування, `exclude`;
  - адмін: вхід, вихід при `401`, список, фільтри, пошук, створення, редагування, приховування, видалення, імпорт CSV/XLSX, головна зі статистикою.
- Автоматизований smoke-скрипт (curl/PHP), що перевіряє ключові ендпоінти за `API.md`, зокрема типи полів.
- Закрити запити `F-001…F-003` (статус `answered` → `done` ставить фронт) і прибрати питання про ліміт з `API.md` разом із підвищенням версії контракту.
- Заповнити `docs/BACKEND.md`: стек, структура, запуск, адреса для `API_PROXY_TARGET`, розгортання, прийняті рішення.
