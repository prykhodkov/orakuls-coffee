# BE-005 · Список і перегляд фраз

| Поле | Значення |
|------|----------|
| Тип | Story |
| Пріоритет | High |
| Компонент | backend |
| Залежить від | BE-004 |
| Блокує | BE-006, BE-008 |

## Опис

Як адмін, я хочу бачити список усіх фраз із фільтрами, пошуком і пагінацією та відкривати окрему фразу, щоб знаходити й редагувати потрібне серед ~600 записів.

Також у цій задачі фіксується сутність `Phrase` та її серіалізація, яку перевикористовують BE-006 і BE-007.

## Обсяг

- `GET /api/admin/phrases` — query-параметри (усі необов'язкові): `category`, `search`, `missing` (`lv|en|ru`), `isActive` (`true|false`), `page` (з 1, за замовч. `1`), `perPage` (1–100, за замовч. `50`).
- Сортування: `id` за спаданням.
- Відповідь: `{ "items": Phrase[], "total", "page", "perPage" }`; `total` — кількість після фільтрів.
- `GET /api/admin/phrases/{id}` → `Phrase` або `404`.
- Серіалізатор `Phrase`: `{ id, category, text: { lv, en, ru }, isActive, createdAt, updatedAt }` з коректними типами (`id` — число, `isActive` — boolean, дати — ISO 8601 UTC).
- `search` — підрядок по всіх трьох мовах; спецсимволи `%`, `_`, `\` екрануються. Пошук **нечутливий до регістру й діакритики** — це наслідок колації `utf8mb4_unicode_ci`, прийнято свідомо (D-13): `sodien` знаходить `Šodien`, `bus` — `būs`. Межі, перевірені на MySQL 5.7: `ё` = `е`, але `й` ≠ `и`; усі емодзі між собою порівнюються як рівні.

## Acceptance criteria

- [ ] Без токена обидва ендпоінти → `401`.
- [ ] `GET /api/admin/phrases` без параметрів → `200`, `page = 1`, `perPage = 50`, не більше 50 елементів, відсортовані за `id` DESC.
- [ ] `id`, `total`, `page`, `perPage` — JSON-числа; `isActive` — `true`/`false`; `text` — об'єкт з трьома ключами `lv`, `en`, `ru` (порожній переклад = `""`).
- [ ] `category=love` повертає лише фрази категорії `love`; невідома категорія → `400 bad_request`.
- [ ] `isActive=false` повертає лише приховані, `isActive=true` — лише активні; інше значення → `400`.
- [ ] `missing=en` повертає лише фрази, де англійський переклад порожній (після trim); невідоме значення → `400`.
- [ ] `search` знаходить підрядок у будь-якій з трьох мов без урахування регістру (напр. `LUCK` знаходить `Luck is on your side`); пошук по кирилиці працює.
- [ ] Пошук ігнорує діакритику: `search=sodien` знаходить фразу з `Šodien`, `search=bus` — з `būs`; регістр не важливий і для кирилиці (`тест` знаходить `Тест`).
- [ ] `search=100%` або `search=_` не трактуються як шаблони LIKE.
- [ ] Фільтри комбінуються (AND): `category` + `missing` + `search` + `isActive`.
- [ ] `total` відповідає кількості записів після фільтрів, а не загальній; `page=2&perPage=10` повертає записи 11–20 у порядку `id` DESC.
- [ ] `page` за межами діапазону → `200` з порожнім `items` і правильним `total`.
- [ ] `perPage=0`, `perPage=101`, `page=0`, нечислові значення → `400 bad_request`.
- [ ] Порожній результат → `items: []` (масив), не `null`.
- [ ] `GET /api/admin/phrases/42` → `200` з повним `Phrase`; неіснуючий `id` або нечисловий `id` → `404 not_found`.
- [ ] Пошук і фільтри виконуються одним-двома SQL-запитами (без N+1), час відповіді < 300 мс на 600 записах.
