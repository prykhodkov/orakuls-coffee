# BE-006 · Створення, оновлення, видалення фраз

| Поле | Значення |
|------|----------|
| Тип | Story |
| Пріоритет | High |
| Компонент | backend |

## Опис

Як адмін, я хочу додавати нові фрази, редагувати наявні (текст, категорію, видимість) та видаляти непотрібні, щоб підтримувати базу послань актуальною.

Валідацію фрази виділити в окремий компонент: її використовує й імпорт (BE-007) — тож вона не кидає виняток на першій помилці, а повертає **всі** помилки полів разом (імпорт збирає їх по рядках).

Захищати ендпоінти окремо не потрібно: усе під `/api/admin/` закрите `AdminGuard` (D-20).

Як фронт це використовує (`frontend/src/shared/validation.js`, `frontend/src/admin/phrase-dialog.js`): шле `{ category, text: { lv, en, ru }, isActive }` (текст ще й обрізає `trim()` у JS); на `422` читає `error.fields` і підсвічує поля за ключами `category`, `text`, `text.lv|en|ru`, `isActive` з кодами `required`, `invalid`, `too_long`, `empty` — саме ці коди та ключі треба віддавати. Після збереження фронт сам перезапитує список.

Прийняті рішення (докладно — `backend/docs/decisions.md`, D-27 … D-29):
- **Валідація — окремий клас у `Domain`** (без залежності від `Http`/`Repository`), повертає нормалізовані дані або повний набір `fields`. Контролер перетворює непорожній набір на `ApiException::validation`. SQL — тільки в `PhraseRepository` (D-17).
- **Обрізання по-юнікодному.** Тексти обрізаються так, як це робить JS `trim()` на фронті: PHP `trim()` не знає про нерозривний пробіл (U+00A0), U+3000, U+FEFF. Інакше фраза з самого `NBSP` пройшла б перевірку «непорожня», зберіглась і потрапила б у видачу `/api/message` порожнім посланням. Це уточнює примітку в `database.md` / D-17 («BE-006 обрізає по-PHP-шному»).
- **Керівні символи в тексті заборонені** (`422`, код `invalid` у відповідному `text.xx`): `U+0000–U+0008`, `U+000B`, `U+000C`, `U+000E–U+001F`, `U+007F`. Дозволені `\n`, `\r`, `\t`. Причина — D-24: пошук у BE-005 використовує `U+0001` і `U+0002` як службові символи, фраза з ними ламала б його. Перенос `\r\n` не нормалізується (зберігається як є).
- **Невідомі ключі ігноруються:** зайві поля верхнього рівня (`id`, `createdAt`… — клієнт може надіслати назад усю отриману фразу) і зайві ключі в `text` (`de`) не помилка й нікуди не потрапляють.
- **Порядок перевірок в обробнику:** формат `id` у шляху (неканонічний → `404`) → тіло (`400` для не-JSON) → валідація полів (`422`) → лише потім звернення до БД (існування → `404`). Тобто `PUT` неіснуючого `id` з невалідним тілом дає `422`, і відхилений запит не виконує жодного SQL.
- **`PUT` — повна заміна**, як у контракті: відсутнє `isActive` означає `true` (так само, як у `POST`), фронт завжди шле його явно.
- Відповіді з `Cache-Control: no-store` (як у BE-005), включно з помилками та `204`.

## Обсяг

- `POST /api/admin/phrases` → `201` + створений `Phrase`.
- `PUT /api/admin/phrases/{id}` → `200` + оновлений `Phrase` (повна заміна `category`, `text`, `isActive`).
- `DELETE /api/admin/phrases/{id}` → `204` без тіла.
- Валідація (усі помилки збираються разом):
  - `category` — обов'язкове (`required`, якщо немає або `null`), одне з `Categories::CODES` (інакше `invalid`; не рядок, `LOVE`, `love ` — теж `invalid`);
  - `text` — обов'язковий об'єкт (`required`, якщо немає; `invalid`, якщо не об'єкт — непорожній список, рядок, число, `null`; порожній `{}`/`[]` — об'єкт без ключів → `text = empty`); ключі `lv`, `en`, `ru`: відсутній ключ і `null` — порожній переклад `""` (не помилка; правило змінено в BE-007, D-30), решта значень мусять бути рядками (інакше `invalid`), можна порожній; після юнікодного trim — до 500 **символів** (`too_long`; не байтів і не UTF-16-одиниць); хоча б одна мова непорожня (`text = empty`; ставиться, лише якщо жодна мова не відхилена за типом);
  - `isActive` — необов'язкове boolean, за замовчуванням `true` (`1`, `"yes"`, `null` → `invalid`).
- Текст зберігається trimmed, plain text, `\n` дозволені, HTML не інтерпретується і не змінюється.
- `createdAt` встановлюється при створенні й не змінюється; `updatedAt` — при кожному оновленні (UTC); при створенні `createdAt = updatedAt` (обидві колонки заповнює один `UTC_TIMESTAMP()`).
- Помилки валідації: `422 validation_error` з `fields`, ключі — шлях до поля (`category`, `text`, `text.lv`, `isActive`); значення — машинний код (`required`, `invalid`, `too_long`, `empty`).
- Тіло запиту, що не є JSON-об'єктом (порожнє, сміття, масив), — `400 bad_request` (це робить `Request::json()`).
- Нові методи `PhraseRepository`: створення, повна заміна, видалення. Відповідь — `Phrase` з БД (`find` після запису), а не зібраний у коді.
- Тестова обв'язка: тести пишуть у `orakuls_test`, тож кожен тест, що змінює дані, повертає таблицю до сіду (`Seeder`), щоб оракули тестів BE-005 і порядок запуску не залежали один від одного.

## Поза обсягом

- Масовий імпорт (BE-007), статистика (BE-008).
- Повторне використання `id` після видалення (InnoDB `AUTO_INCREMENT` на MySQL 5.7 може віддати `id` останнього видаленого запису після перезапуску сервера). Наслідок мізерний: лише одну фразу фронт один раз «вважатиме баченою» через `exclude`.
- Лічильник довжини на фронті рахує одиниці UTF-16 (`emoji` = 2), бекенд — символи (`emoji` = 1): бекенд м'якший, розбіжність у безпечний бік; контракт не змінюємо.
- Зміна `API.md`: поведінка йому відповідає.

## Acceptance criteria

- [x] Без токена всі три ендпоінти → `401` (забезпечує guard; перевірити тестом), навіть із невалідним тілом.
- [x] `POST` з валідним тілом → `201`, у відповіді `Phrase` з новим числовим `id`, `isActive: true` (якщо не передано), `createdAt = updatedAt`, дати в ISO 8601 UTC.
- [x] Після `POST` фраза з'являється в `GET /api/admin/phrases` та `GET /api/admin/phrases/{id}` і збігається з відповіддю `POST`.
- [x] `POST` без `category`, з `null` → `422`, `fields.category = "required"`; невідома категорія (`LOVE`, `love `, число, масив) → `fields.category = "invalid"`.
- [x] `POST` із `text`, де всі три мови порожні (чи лише пробіли, у т. ч. нерозривні `U+00A0`, `U+3000`) → `422`, `fields.text = "empty"`.
- [x] `POST` із текстом 500 символів → `201`; 501 символ → `422`, `fields["text.lv"] = "too_long"` (лічильник у символах, а не байтах: рядок із 500 символів `š`/`я`/емодзі проходить).
- [x] Текст, що після trim вкладається в 500, але з пробілами навколо перевищує — проходить; збережений текст — trimmed (юнікодні пробіли теж).
- [x] `text` відсутній → `fields.text = "required"`; `text` не об'єкт → `invalid`; відсутній ключ мови або `null` → порожній переклад (D-30, не помилка); не рядкове значення (число, bool, масив) → `fields["text.xx"] = "invalid"`.
- [x] `isActive` не boolean (`"yes"`, `1`, `null`) → `422`, `fields.isActive = "invalid"`.
- [x] Кілька помилок одразу повертаються разом в одному `fields`.
- [x] Текст із керівними символами (`\0`, `\x01`, `\x02`, `\x7F`) → `422`, `fields["text.xx"] = "invalid"`; `\n`, `\r\n`, `\t` проходять і не змінюються.
- [x] Некоректний JSON, порожнє тіло, масив замість об'єкта → `400 bad_request`; недійсний UTF-8 / lone surrogate (`\ud800`) в JSON → `400`, не `500`.
- [x] Зайві поля (`id`, `createdAt`, `text.de`) ігноруються: `id` з тіла не змінює `id` фрази.
- [x] Переноси рядків `\n` зберігаються і повертаються без змін; текст із `<script>` зберігається як є, без екранування/видалення; емодзі та діакритика не спотворюються.
- [x] `PUT` повністю замінює `category`, `text`, `isActive`; `createdAt` не змінюється, `updatedAt` оновлюється; відповідь `200` містить оновлений `Phrase`; відсутнє `isActive` → `true`.
- [x] `PUT` неіснуючого `id` → `404`; неканонічний `id` (`007`, `abc`, `0`, `1.5`) → `404`; невалідні дані → `422` і запис у БД не змінюється (в т. ч. для неіснуючого `id`).
- [x] `PUT` з `isActive: false` прибирає фразу з видачі `GET /api/message`; з `true` — повертає.
- [x] Очищення перекладу (`text.en = ""`) через `PUT` → фраза зникає з видачі `/api/message` для `en`, але лишається для інших мов; `GET /api/admin/phrases?missing=en` її показує.
- [x] `DELETE` існуючої → `204` з порожнім тілом; повторний `GET` цього `id` → `404`; повторний `DELETE` → `404`.
- [x] `DELETE` неіснуючої або неканонічної → `404 not_found`.
- [x] Усі відповіді (і помилки, і `204`) мають `Cache-Control: no-store`.
- [x] SQL-ін'єкції у полях не виконуються (prepared statements); спецсимволи (`%`, `_`, `\`, `'`) зберігаються без спотворень.
- [x] Відхилений запит (`400`/`404` за форматом `id`/`422`) не виконує жодного SQL; успішний `POST`/`PUT` — не більше двох (запис + `find`), `DELETE` — один.
- [x] Валідація — окремий клас без залежності від `Http`/`Repository`, придатний для BE-007 (повертає всі помилки, не кидає виняток); покритий юніт-тестами `tests/run.php`.
- [x] Тести, що змінюють дані, повертають таблицю до сіду; повторний запуск `tests/api.php` двічі поспіль зелений.
- [x] Нові D-xx записані в `decisions.md`; документація (`security.md`, `database.md`, `api-conventions.md`, `architecture.md`, `testing.md`, `docs/BACKEND.md`) оновлена, примітка про «PHP trim» виправлена.
