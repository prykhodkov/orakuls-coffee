# BE-003 · `GET /api/message` — випадкове послання

| Поле | Значення |
|------|----------|
| Тип | Story |
| Пріоритет | High |
| Компонент | backend |
| Залежить від | BE-001, BE-002 |

## Опис

Як відвідувач, що відсканував QR-код зі стаканчика і обрав мову, я хочу отримати випадкове послання своєю мовою, щоб побачити його на екрані.

Ендпоінт публічний (без авторизації). Це єдиний ендпоінт, який викликають користувачі, тож він має бути швидким і стійким до некоректного вводу. Фронт ніколи не отримує всю базу — випадковість обирає бекенд.

## Обсяг

- `GET /api/message?lang=lv|en|ru&exclude=1,2,3`
- Кандидати: фрази з `is_active = 1` і непорожнім (після trim) текстом мовою `lang`; категорії рівноправні, усі разом.
- Рівномірно випадковий вибір одного запису.
- `exclude` — ID через кому. Фрази з `exclude` виключаються з кандидатів; якщо після виключення кандидатів не лишилось — `exclude` ігнорується.
- Відповідь `200`: `{ "id": 42, "lang": "lv", "text": "…" }` — `id` числом.
- Заголовок `Cache-Control: no-store`.
- Ліміту на кількість посланнь немає (F-002).

## Acceptance criteria

- [ ] `GET /api/message?lang=lv` повертає `200` з тілом рівно `{ id, lang, text }`, де `id` — число, `lang` збігається із запитаним, `text` непорожній.
- [ ] Відповідь містить `Cache-Control: no-store`.
- [ ] Без параметра `lang` або з невідомим `lang` (`de`, порожній) → `400 bad_request`.
- [ ] Фраза з `is_active = 0` ніколи не повертається.
- [ ] Фраза з порожнім або лише з пробілів перекладом мовою `lang` не повертається для цієї мови, але може повертатись для інших.
- [ ] Якщо в БД немає жодної доступної фрази для `lang` → `404 not_found`.
- [ ] ID із `exclude` не повертаються, поки є інші кандидати (перевірка на 200 запитах).
- [ ] Якщо `exclude` покриває всі доступні фрази — повертається `200` із будь-якою доступною (а не `404`).
- [ ] Некоректний `exclude` (`abc`, `1,,2`, від'ємні числа) → `400 bad_request`; пробіли навколо чисел толеруються. Максимальна довжина/кількість ID обмежена розумним значенням (≥ 100 ID, ~500 символів — як на фронті) без падіння.
- [ ] Розподіл рівномірний: на тестовій БД `orakuls_test` (див. BE-002) з N доступних фраз кожна з'являється зі статистично схожою частотою (перевірка скриптом на ≥ 1000 запитів).
- [ ] Запит не робить повного завантаження таблиці в PHP — вибір відбувається в SQL.
- [ ] Час відповіді на базі ~600 фраз < 200 мс локально.
- [ ] Ендпоінт не вимагає `Authorization` і не повертає полів `category`, `isActive`, дат.
