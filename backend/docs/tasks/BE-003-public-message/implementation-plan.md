## 1. Підтверджені факти

Перевірено експериментами на реальному `mysql:5.7` і PHP 8.4 у Docker проєкту (на сіді з `orakuls_test`). Не перевіряй наново, але й не ігноруй.

| # | Факт | Наслідок |
|---|------|----------|
| 1 | `SELECT … WHERE is_active=1 AND TRIM(col)<>'' ORDER BY RAND() LIMIT 1` працює; на 3000 запитів для `lv` (28 кандидатів) лічильники 89…119 при середньому 107.1 і σ=10.16 | Вибір рівномірний; смуга ±6σ = [46…168] проходить із великим запасом |

## 2. Дизайн-рішення цього плану

1. **Один запит, жодного запасного.** `ORDER BY (id IN (…)) ASC, RAND() LIMIT 1`: вираз у дужках дає `0` для непереглянутих і `1` для виключених, тож спершу йдуть непереглянуті (у випадковому порядку), а якщо їх нема — виключені. Це реалізує правило «ігнорувати `exclude`, якщо нічого не лишилось» (факт 3).
2. **Імена колонок — лише з `Languages::column()`.** Ввід користувача в SQL не підставляється; `lang` спершу проходить `Languages::isValid()`.
3. **`exclude` розбирає окремий чистий клас `Support\IdList`** (без БД і HTTP) — легко тестується юніт-перевірками.
4. **Шар `Repository`.** SQL живе в `Repository\PhraseRepository`, контролер тонкий (D-17). Репозиторій приймає `PDO` у конструкторі, сам `Db::pdo()` не викликає.
5. **Критерій «порожній» — одне місце.** `PhraseRepository::hasTextSql(string $lang): string` повертає `TRIM(<колонка>) <> ''`; BE-005/BE-008 використовуватимуть його ж.
6. **Контролер не логує 4xx** (за `error-handling.md`).

## 4. Кроки реалізації

Кожен крок завершується перевіркою; не переходь далі з червоними тестами. Усі файли PHP пиши інструментами Write/Edit, **не через heredoc у Bash**: оболонка зменшує подвійні зворотні слеші (`\\` → `\`) і псує код (так уже траплялось у BE-002).

### Крок 1 · `Request::rawQuery()` і `IdList`

**1.1.** У `src/Http/Request.php` додай (поруч із `query()`):

```php
/**
 * Сире значення параметра без перевірок: рядок, масив або null.
 * Для параметрів-підказок (exclude), де некоректний ввід має ігноруватись, а не давати 400.
 */
public function rawQuery(string $name): mixed
{
    return $this->query[$name] ?? null;
}
```

`query()` лишається без змін (для `lang`: масив → `400`).

**1.2.** `src/Support/IdList.php`:

```php
final class IdList
{
    /** Скільки коректних ID враховуємо: удвічі більше за 100, які тримає фронт (D-18). */
    public const MAX_IDS = 200;

    /** Верхня межа кількості фрагментів, які взагалі розглядаємо (захист від гігантських рядків). */
    private const MAX_TOKENS = 1000;

    /**
     * 'exclude' з query → список унікальних ID у порядку появи. Ніколи не кидає винятків.
     *
     * @return list<int>
     */
    public static function parse(?string $raw, int $max = self::MAX_IDS): array;
}
```

Алгоритм `parse`:
1. `null` або порожній рядок → `[]`.
2. `explode(',', $raw, self::MAX_TOKENS)` — з лімітом: останній елемент містить «решту» рядка разом із комами, не пройде перевірку нижче і буде пропущений.
3. Для кожного фрагмента: `trim()`; якщо `preg_match('/^\d{1,10}$/', $part) !== 1` — пропустити (без `/u`: `\d` — лише ASCII-цифри). Інакше `(int) $part`.
4. Пропустити, якщо такий ID уже є (зберегти перший; для швидкості — асоціативний масив-лічильник).
5. Зупинитись, коли зібрано `$max` ID.

Нулі на початку (`007`) дозволені → `7`; `0` теж валідний (безпечний). Значення до 9 999 999 999 вміщується в 64-бітний `int`; ID більші за `INT UNSIGNED` просто нічого не знайдуть.

**Юніт-перевірки** (у `tests/run.php`, без БД) — таблиця «вхід → результат»:

| Вхід | Результат |
|------|-----------|
| `null`, `''` | `[]` |
| `'5'` | `[5]` |
| `'5,12,40'` | `[5,12,40]` |
| `' 5 , 12 '` | `[5,12]` |
| `'5,abc,40'` | `[5,40]` |
| `'1,,2'`, `',,,'` | `[1,2]`, `[]` |
| `'-5'`, `'+5'`, `'1.5'`, `'1e3'` | `[]` |
| `'12345678901'` (11 цифр) | `[]` |
| `'4294967295'` | `[4294967295]` |
| `'007'` | `[7]` |
| `'5,5,6,5'` | `[5,6]` |
| арабсько-індійська цифра `'٣'` | `[]` |
| 300 різних ID, `max` за замовчуванням | перші 200 |
| `'1,2,3,4,5'`, `max = 3` | `[1,2,3]` |
| сміття перед коректними: `'abc,x,7'` | `[7]` (сміття не займає місце в ліміті) |
| 1500 коректних ID в одному рядку | не кидає виняток, довжина ≤ 200 |
| рядок 1 МБ із `a,` | `[]` без винятків |

Окремо для `Request::rawQuery`: повертає рядок, масив і `null` як є.

### Крок 2 · `PhraseRepository`

`src/Repository/PhraseRepository.php`:

```php
namespace App\Repository;

final class PhraseRepository
{
    public function __construct(private readonly PDO $pdo) {}

    /**
     * SQL-умова «переклад мовою $lang не порожній». Єдине визначення порожнього для всіх ендпоінтів (BE-003, BE-005, BE-008).
     * TRIM прибирає лише пробіли: BE-006 при записі обрізає всі пробільні символи.
     */
    public static function hasTextSql(string $lang): string
    {
        return 'TRIM(`' . Languages::column($lang) . '`) <> \'\'';
    }

    /**
     * Випадкова активна фраза з непорожнім перекладом. Фрази з $excludeIds вибираються лише коли інших немає.
     *
     * @param list<int> $excludeIds
     * @return array{id: int, text: string}|null null — кандидатів немає
     */
    public function findRandom(string $lang, array $excludeIds = []): ?array;
}
```

`findRandom`:
1. `$column = Languages::column($lang)` (кидає `InvalidArgumentException` на невідомий код — це помилка програміста, не користувача; контролер перевіряє `lang` раніше).
2. SQL (значення `$column` — лише з білого списку, тому його можна вставити в рядок):

```php
$sql = "SELECT `id`, `{$column}` AS `text` FROM `phrases` WHERE `is_active` = 1 AND " . self::hasTextSql($lang);
if ($excludeIds === []) {
    $sql .= ' ORDER BY RAND() LIMIT 1';                       // IN () порожнім не буває — синтаксична помилка (факт 5)
} else {
    $in = implode(',', array_fill(0, count($excludeIds), '?'));
    $sql .= " ORDER BY (`id` IN ({$in})) ASC, RAND() LIMIT 1"; // непереглянуті першими, потім виключені
}
```

3. `prepare`, потім для кожного `$i => $id` — `bindValue($i + 1, $id, PDO::PARAM_INT)` (позиційні параметри нумеруються **з 1**), `execute`, `fetch()` один рядок.
4. `false` → `null`; інакше `['id' => (int) $row['id'], 'text' => (string) $row['text']]`.

Не використовуй `fetchAll`, не завантажуй кандидатів у PHP, не вибирай випадковий номер у PHP (`ORDER BY RAND()` на ~600 рядках — ~1 мс).

### Крок 3 · `MessageController` і маршрут

`src/Controller/MessageController.php`:

```php
public function show(Request $request, array $params): Response
{
    $lang = $request->query('lang');                         // масив → 400 (query() кидає)
    if ($lang === null || !Languages::isValid($lang)) {      // порожній, невідомий, 'LV' → 400
        throw ApiException::badRequest('Parameter lang is required: lv, en or ru');
    }

    $raw = $request->rawQuery('exclude');                    // НЕ query(): масив має ігноруватись, а не давати 400
    $exclude = IdList::parse(is_string($raw) ? $raw : null);

    $row = (new PhraseRepository(Db::pdo()))->findRandom($lang, $exclude);
    if ($row === null) {
        throw ApiException::notFound('No phrases available for this language');
    }

    return Response::json(
        ['id' => $row['id'], 'lang' => $lang, 'text' => $row['text']],   // порядок ключів фіксований
        200,
        ['Cache-Control' => 'no-store']
    );
}
```

`Db::pdo()` викликається всередині обробника (ліниво): створення контролера в `routes.php` БД не відкриває.

У `src/routes.php` додай рядок поруч із health:

```php
$router->get('/api/message', [new MessageController(), 'show']);
```

### Крок 4 · Тестова обв'язка

У `tests/lib.php` додай (файл вже підключають і `run.php`, і `api.php`; функції не повинні вимагати БД при визначенні):

```php
/** Один Kernel на процес: маршрути завантажуються раз, а не на кожен із тисяч запитів. */
function apiKernel(): Kernel
{
    static $kernel = null;

    return $kernel ??= Kernel::create();
}

/** Виклик API в процесі, без HTTP-сервера. $query — вже розібраний query ('exclude' => '1,2' або ['1','2']). */
function apiRequest(string $method, string $path, array $query = [], array $headers = [], string $body = ''): Response
{
    return apiKernel()->handle(new Request($method, $path, $query, $headers, $body));
}

/**
 * Перевіряє рівномірність розподілу вибірок: кожен із $candidates зустрівся, а лічильник кожного
 * у межах ±6σ від середнього. Смуга свідомо широка: шанс хибного спрацювання ~1e-8, тест не повинен «блимати».
 *
 * @param list<int> $candidates
 * @param array<int,int> $counts id → скільки разів випав
 */
function assertUniform(array $candidates, array $counts, int $draws): void;
```

Математика для `assertUniform`: `N = count($candidates)`, `mean = draws / N`, `sd = sqrt(draws * (1/N) * (1 - 1/N))`, межі `mean ± 6*sd`; повідомлення про помилку має містити id, лічильник і межі. Також перевір, що жоден id **поза** `$candidates` не випав (`$counts` не містить зайвих ключів). Додай `use App\Http\Request;` у `lib.php`.

Деталі виконання:
- Вимір `Bytes_sent`: `SHOW SESSION STATUS LIKE 'Bytes_sent'` повертає пару (ім'я, значення), читай `fetch(PDO::FETCH_NUM)[1]`. Сам вимірювальний `SHOW` додає ~358 байт — відніми «порожню» дельту (два `SHOW` поспіль), як у експерименті, або просто порівнюй відношення, воно від цього не залежить. Одна й та сама сесія: `Kernel` і тест працюють через спільний `Db::pdo()`, тому вставлені в транзакції рядки видимі запиту ендпоінта.
- Тест 13/14: `beginTransaction()` → вставка → вимірювання → `rollBack()` у `finally` → `reseed()` (відкат не повертає `AUTO_INCREMENT`, а `reseed()` робить `TRUNCATE`).
- Для 600 «довгих» рядків тексту `lv` бери ≈ 100 символів (інакше різниця дельт мала); у експерименті було `str_repeat("Фраза номер $i. ", 6)`.
- Тести 5, 7 і 11 — по 3000 запитів (~1 с кожен). Не зменшуй кількість: від неї залежить і надійність смуги ±6σ, і її чутливість (див. тест 7).
- Тест 12 «сире тіло»: для детермінізму залиши активною лише одну потрібну фразу (`UPDATE phrases SET is_active = 0 WHERE id <> ?`), порівняй `$response->body` рядково, потім `reseed()`.
- Тест 3: `lang[]=lv` задається як `['lang' => ['lv']]` у масиві query (так його збере `Request::fromGlobals()` з `$_GET`).

## 5. Пастки

1. **`IN ()` порожній — синтаксична помилка.** При порожньому `exclude` не додавай ні `IN`, ні `ORDER BY (…)`.
2. **`Request::query()` кидає `400` на масив** — для `exclude` використовуй `rawQuery()`, для `lang` — `query()`.
3. **`bindValue` нумерується з 1**, а масив `$excludeIds` — з 0 (`$i + 1`).
4. **Ім'я колонки не можна передати параметром** — лише `Languages::column()`. Ніколи `"text_{$lang}"` напряму.
5. **`TRIM` в SQL ≠ `trim` у PHP** (лише пробіли проти всіх пробільних). Критерій «порожній» береш тільки з `hasTextSql()`, не пиши власну версію в PHP для фільтрації кандидатів.
6. **`Rows_sent` у MySQL 5.7 немає** — використовуй `Bytes_sent`.
7. **Не звужуй смугу ±6σ** і не зменшуй число запитів у статистичних тестах: інакше з'являться нестабільні (flaky) падіння.
8. **Один `Kernel` на тест** (`apiKernel()`), не `Kernel::create()` у циклі на 3000 ітерацій.
9. **`reseed()` у `finally`** кожного тесту, що змінив дані; після відкату транзакції `AUTO_INCREMENT` не повертається, `TRUNCATE` у `reseed()` це лагодить.
10. **Heredoc у Bash з `\\`** псує код — пиши файли через Write/Edit.
11. **Не логуй 4xx**, не логуй значення `exclude`.
12. **Не змінюй `Response::json` і формат помилок** — це спільний код; `Cache-Control: no-store` для `200` передається явно в контролері.
13. **`id` приводь до `int` на межі БД → JSON** (D-09), текст — як є, без `htmlspecialchars` і без `trim`.
