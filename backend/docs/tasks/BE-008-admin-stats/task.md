# BE-008 · `GET /api/admin/stats`

| Поле | Значення |
|------|----------|
| Тип | Story |
| Пріоритет | Medium |
| Компонент | backend |
| Залежить від | BE-005 |

## Опис

Як адмін, я хочу бачити на головній адмінки зведення по базі фраз (скільки всього, скільки активних, розподіл за категоріями, у скількох бракує перекладів), щоб розуміти, що ще треба дописати.

## Обсяг

- `GET /api/admin/stats` → `200`:

```json
{
  "total": 600,
  "active": 595,
  "byCategory": { "love": 100, "money": 100, "luck": 100, "work": 100, "travel": 100, "mood": 100 },
  "missing": { "lv": 0, "en": 12, "ru": 3 }
}
```

- `total` — усі фрази; `active` — з `isActive = true`.
- `byCategory` — кількість фраз кожної категорії; присутні **всі** 6 категорій, навіть із нулем.
- `missing` — кількість фраз із порожнім (після trim) перекладом по кожній мові; присутні всі 3 мови.
- Підрахунок — агрегуючими SQL-запитами (`COUNT`, `SUM(CASE …)`/`GROUP BY`), без завантаження фраз у PHP; сумісно з MySQL 5.7.

## Acceptance criteria

- [ ] Без токена → `401`.
- [ ] Усі значення — JSON-числа; `byCategory` і `missing` — об'єкти.
- [ ] На порожній БД: `total = 0`, `active = 0`, `byCategory` містить усі 6 категорій зі значенням `0`, `missing` — усі 3 мови зі значенням `0` (об'єкти не перетворюються на `[]`).
- [ ] `total` дорівнює `total` з `GET /api/admin/phrases` без фільтрів.
- [ ] `active` дорівнює `total` з `GET /api/admin/phrases?isActive=true`.
- [ ] Сума значень `byCategory` дорівнює `total`.
- [ ] `missing.en` дорівнює `total` з `GET /api/admin/phrases?missing=en` (аналогічно для `lv`, `ru`); переклад із самих пробілів вважається порожнім.
- [ ] Статистика відображає зміни одразу: після створення/видалення/приховання фрази значення оновлюються без кешу.
- [ ] Відповідь формується не більше ніж за 3 SQL-запити, < 200 мс на 600 записах.
