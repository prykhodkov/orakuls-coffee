## Опис

Створити основу бекенда на PHP 8.4, на якій будуть реалізовуватись усі ендпоінти: точка входу, роутер, читання конфігурації, єдиний формат відповідей і помилок, підключення до MySQL 5.7.

Хостинг — GoDaddy cPanel (shared, Apache), тому рішення працюють без root-доступу і без довгоживучих процесів. Рішення по стеку: без фреймворка і без Composer, локальне оточення в Docker (див. `docs/BACKEND.md`).

## Обсяг

- Структура `backend/`: публічна точка входу (`public/index.php`), код застосунку поза веб-коренем (`src/`), конфіг, міграції (з BE-002).
- Docker-оточення: PHP 8.4 + MySQL 5.7 (`docker-compose.yml`).
- Роутер: метод + шаблон шляху з параметром `{id}` → обробник. Усі шляхи під `/api`.
- Конфігурація з `.env` поза репозиторієм, змінні процесу мають пріоритет. Приклад — `.env.example`; реальний `.env` — у `.gitignore`.
- Хелпери відповіді: `Response::json(data, status)`, порожня відповідь `204`.
- Помилки з кодами з `API.md`: `bad_request` (400), `unauthorized` (401), `not_found` (404), `validation_error` (422, з `fields`), `rate_limited` (429), `server_error` (500).
- Глобальний обробник винятків і PHP-помилок: жодних stack trace у відповіді, деталі — у лог.
- Підключення PDO: `utf8mb4`, `ERRMODE_EXCEPTION`, `EMULATE_PREPARES=false`, `STRINGIFY_FETCHES=false`.
- Читання JSON-тіла запиту з валідацією (`400 bad_request` на некоректний JSON).
- Серіалізація: `JSON_UNESCAPED_UNICODE`, порожні асоціативні масиви → `{}`.
- Службовий `GET /api/health` (поза контрактом `API.md`).
- Інструкція локального запуску в `docs/BACKEND.md`.

## Поза обсягом

Бізнес-логіка ендпоінтів, схема БД (BE-002), `.htaccess` для хостингу (BE-009).

## Acceptance criteria

- [x] Проєкт запускається локально на PHP 8.4 однією задокументованою командою (`docker compose up -d --build`), інструкція є в `docs/BACKEND.md`.
- [x] Запит на неіснуючий шлях під `/api` повертає `404` у форматі `{ "error": { "code": "not_found", "message": "…" } }`.
- [x] Запит із непідтримуваним методом на існуючий шлях повертає `404 not_found` (рішення зафіксоване в `BACKEND.md`).
- [x] Тіло запиту з некоректним JSON повертає `400 bad_request` (перевірено на рівні `Request::json()`; ендпоінтів із тілом поки немає).
- [x] Необроблений виняток і PHP warning повертають `500 server_error` без stack trace і без внутрішніх шляхів; деталі пишуться стандартним `error_log()` (власних файлів логів немає).
- [x] Усі відповіді мають `Content-Type: application/json; charset=utf-8`.
- [x] Порожній асоціативний масив серіалізується як `{}`, а не `[]` (є тест).
- [x] Кирилиця і латиська (`š`, `ā`, `ē`…) у відповідях не екрануються (`JSON_UNESCAPED_UNICODE`, є тест).
- [x] Цілі числа з БД віддаються числами, не рядками (перевірено реальним запитом до MySQL 5.7: `int(1)`).
- [x] Секрети читаються з конфігурації поза репозиторієм; `.env.example` є, `.env` у `.gitignore`.
- [x] Підключення до БД використовує `utf8mb4`, prepared statements без емуляції, строгий `sql_mode`.
- [x] У коді немає залежностей від можливостей PHP > 8.4 чи MySQL 8.x.
- [x] `GET /api/health` → `200 {"status":"ok"}`, коли БД доступна; `503 {"status":"error"}`, коли ні (деталі лише в лозі, версій у відповіді немає).
- [x] У відповідях немає заголовка `X-Powered-By`.
