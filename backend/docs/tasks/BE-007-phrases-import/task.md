# BE-007 · Масовий імпорт фраз

| Поле | Значення |
|------|----------|
| Тип | Story |
| Пріоритет | Medium |
| Компонент | backend |
| Залежить від | BE-006 |

## Опис

Як адмін, я хочу завантажити сотні фраз одним запитом (з CSV/Excel), щоб швидко наповнити базу. Файл розбирає фронт і шле готовий масив; бекенд валідує кожен елемент, зберігає валідні, а по невалідних повертає звіт.

## Обсяг

- `POST /api/admin/phrases/import`, тіло `{ "items": [ { "category", "text": { "lv", "en", "ru" } }, … ] }`.
- До 1000 елементів за запит.
- Кожен елемент валідується тими ж правилами, що й створення фрази (BE-006); `isActive` для імпортованих — `true`.
- Валідні зберігаються, невалідні пропускаються (часткове збереження, а не все-або-нічого).
- Відповідь `200`: `{ "created": N, "errors": [ { "index": i, "fields": { … } } ] }`; `index` — позиція в `items` з 0.
- Лише додавання; наявні фрази не змінюються і не дедуплікуються.
- Вставка пакетами в транзакції (швидко на shared-хостингу, не впирається в `max_execution_time`).

## Відкрите питання (узгодити з фронтом через `BACK-TO-FRONT.md`)

`API.md` не описує відповідь на `items` довше за 1000 або відсутній/не масив. Пропозиція: `422 validation_error`, `fields.items = "too_many" | "invalid"`. Не реалізовувати, доки не узгоджено.

## Acceptance criteria

- [ ] Без токена → `401`.
- [ ] Запит із 600 валідних елементів → `200`, `created = 600`, `errors = []` (масив), у БД з'являється 600 нових записів, усі `isActive = true`.
- [ ] Елемент з невідомою категорією → пропущений, у `errors` є `{ index, fields: { category: "invalid" } }`; решта зберігається.
- [ ] Елемент, де всі три переклади порожні → пропущений, `fields: { text: "empty" }`.
- [ ] Елемент з перекладом довшим за 500 символів → пропущений, `fields` вказує на відповідну мову (`text.lv: "too_long"` тощо).
- [ ] `created + errors.length = items.length` для будь-якого запиту.
- [ ] `index` у `errors` збігається з позицією елемента у вхідному масиві (з 0) і не зсувається через пропущені елементи.
- [ ] Елемент без одного з ключів мови (`text: { lv, ru }`) трактується як порожній переклад `en`, а не як помилка, якщо хоча б одна мова непорожня (рішення зафіксоване в `BACKEND.md`).
- [ ] Порожній масив `items: []` → `200`, `created = 0`, `errors = []`.
- [ ] 1000 елементів обробляються успішно за < 10 с; перевищення ліміту / відсутній `items` поводяться за узгодженим рішенням (див. відкрите питання).
- [ ] Повторний імпорт того самого набору створює дублікати (існуючі не змінюються) — це очікувана поведінка.
- [ ] Фраза з помилковим елементом не залишає «напівзбережених» даних: у БД немає записів для елементів зі списку `errors`.
- [ ] Збій БД посеред запиту не залишає частково вставленого пакета (транзакція відкочується) і дає `500 server_error`.
- [ ] Імпортовані фрази одразу доступні в `GET /api/admin/phrases` і (якщо мають текст відповідною мовою) в `GET /api/message`.
