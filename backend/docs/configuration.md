# Конфігурація

Конфігурація — змінні з файлу `.env` та змінні процесу. **Змінні процесу мають пріоритет над файлом** (зручно для CI та Docker).

## Де що лежить

| Файл | У git | Призначення |
|------|-------|-------------|
| `backend/.env.example` | так | Шаблон із заглушками — документує, які змінні існують |
| `backend/.env` | **ні** (`.gitignore`) | Реальні значення на конкретному оточенні |

Файл читає `Support\Config::load()` із `APP_ROOT/.env` (`APP_ROOT` — корінь застосунку, `bootstrap.php` визначає його як батьківську папку `src/`). Якщо файлу немає — це не помилка; обов'язкові змінні перевіряються при першому використанні, і `Config::require()` кидає виняток із назвою відсутньої змінної.

## Формат `.env`

```
# коментар
KEY=value
KEY="значення з пробілами"
HASH='$2y$10$abc…'
```

- Один рядок — одна змінна; порожні рядки й `#`-коментарі ігноруються.
- Лапки (`"…"` або `'…'`) знімаються. **Інтерполяції нема** — `$` береться як звичайний символ, тому хеші паролів безпечні (але краще брати в лапки).

## Змінні

| Змінна | Обов'язкова | За замовчуванням | Призначення |
|--------|-------------|------------------|-------------|
| `DB_HOST` | так | — | Хост MySQL. У Docker — `db` |
| `DB_PORT` | ні | `3306` | Порт MySQL |
| `DB_NAME` | так | — | Назва бази (локально `orakuls`). Тести ендпоінтів (`tests/api.php`) самі підставляють `orakuls_test` і від цього значення не залежать |
| `DB_USER` | так | — | Користувач БД |
| `DB_PASS` | ні | порожній | Пароль БД |
| `DB_ROOT_PASS` | лише Docker | `root` | Root-пароль локального MySQL; читає `docker-compose.yml`, застосунок — ні |
| `ADMIN_LOGIN` | з BE-004 | — | Логін єдиного адміна |
| `ADMIN_PASSWORD_HASH` | з BE-004 | — | Хеш пароля адміна (`password_hash`), не сам пароль |
| `TOKEN_SECRET` | з BE-004 | — | Ключ підпису токена; довгий випадковий рядок, на кожному оточенні свій |
| `TOKEN_TTL_HOURS` | з BE-004 | `24` | Термін дії токена |

`docker-compose.yml` підставляє `DB_NAME`, `DB_USER`, `DB_PASS`, `DB_ROOT_PASS` у контейнер MySQL (зі значеннями за замовчуванням `orakuls`/`orakuls`/`orakuls`/`root`), тому `.env` і локальна БД завжди узгоджені.

## Секрети

- Реальні значення — лише в `backend/.env` на потрібній машині, у репозиторій не потрапляють.
- Пароль адміна зберігається **тільки як хеш**.
- На хостингу `.env` лежить поза `public_html` (див. [deployment.md](deployment.md)).
- Значення секретів не логуються й не повертаються в API.

## Додати нову змінну

1. Прочитати її через `Config::get('NAME', 'default')`, `Config::require('NAME')` або `Config::bool('NAME')`.
2. Додати в `.env.example` із коментарем.
3. Додати рядок у таблицю вище.
