# Тестування

PHPUnit не використовуємо (немає Composer), тож перевірки — невеликі скрипти без залежностей. Усі повертають код виходу `0` при успіху й `1` при провалі, тому підходять для CI.

## Рівні (зараз — два, третій з'явиться в BE-002)

| Скрипт | Що перевіряє | Потрібна БД | Команда |
|--------|--------------|-------------|---------|
| `tests/run.php` | Логіку каркаса напряму, без HTTP: роутер, `Request`, `Json`, формат помилок, `Config` | ні | `docker compose run --rm --no-deps php php tests/run.php` |
| `tests/smoke.php` | Запущений API по HTTP: статуси, заголовки, тіла відповідей | так | `docker compose exec php php tests/smoke.php [base-url]` |

### `tests/run.php` — юніт-перевірки

Невелика власна обв'язка:

```php
test('опис того, що перевіряємо', function () {
    $kernel = kernelWith(fn (Router $r) => $r->get('/api/x', fn () => Response::json(['ok' => true])));

    $response = $kernel->handle(new Request('GET', '/api/x'));

    assertSame(200, $response->status);
});
```

- `test($name, $fn)` реєструє перевірку; будь-який виняток усередині — провал.
- `assertSame($expected, $actual)` — сувора рівність (`===`), `assertTrue($cond)`.
- `kernelWith(fn (Router $r) => …)` створює `Kernel` з довільними маршрутами, не торкаючись `routes.php`.
- `decode($response)` розбирає тіло відповіді в масив.
- `error_log()` перенаправлено в тимчасовий файл, тож можна перевірити, що деталі помилки потрапили в лог, а не у відповідь.

Зараз покрито: параметри шляху; `404` для невідомого шляху й методу; `400` на некоректне тіло й параметр-масив; кодування JSON (юнікод, числа, `{}` замість `[]`); формат кожної помилки й відповідність кодів `API.md`; `500` без витоку деталей; перетворення PHP warning на `500`; розбір `.env`.

### `tests/smoke.php` — перевірка по HTTP

Бере базову адресу з аргументу, змінної `BASE_URL` або `http://localhost:8000`. Перевіряє `/api/health`, формат `404`, метод, якого немає для шляху, кінцевий слеш.

Те саме можна запустити проти хостингу (з контейнера, бо PHP на машині немає):

```
docker compose run --rm --no-deps php php tests/smoke.php https://<домен>
```

Поточні перевірки лише читають, тож безпечні для прода. Smoke-перевірки, що створюють або видаляють дані (CRUD фраз, імпорт), у прод запускати не можна без окремого рішення.

## Як додати перевірку

1. Нова логіка без БД → `test(…)` у `tests/run.php`.
2. Поведінка запущеного сервера «знизу вгору» (статус, заголовки), безпечна для прода → блок у `tests/smoke.php`.
3. Ендпоінт, що читає чи пише в БД (після BE-002) → `tests/api.php` на відомих даних сіду; новий випадок — в сід.
4. Перевіряти і щасливий шлях, і помилки (`400`, `401`, `404`, `422`) разом із **типами полів** (`42`, а не `"42"`; `true`, а не `1`).

## Третій рівень: ендпоінти проти тестової БД (⏳ BE-002)

Перевірки ендпоінтів з БД (випадковий вибір без повторів, фільтри та пагінація, валідація, імпорт) потребують відомих даних. Для цього — окрема база `orakuls_test` і скрипт `tests/api.php` ([рішення D-14](decisions.md)).

| Скрипт | Що робить | Команда |
|--------|-----------|---------|
| `tests/api.php` | Сам застосовує міграції до `orakuls_test`, очищає таблиці, заливає сід, викликає `Kernel` у процесі (без HTTP) і перевіряє відповіді | `docker compose exec php php tests/api.php` |

Чому в процесі, а не по HTTP: запущений на :8000 сервер працює з робочою БД з `.env`, тож HTTP-тести не мали б відомих даних. `tests/api.php` сам обирає `orakuls_test` і не залежить від `DB_NAME` у `.env`.

- **Запобіжник.** Скрипт і `bin/seed.php` завершуються з помилкою, якщо назва БД не закінчується на `_test` — локальні дані й прод недоторкані.
- **Сід** лежить у репозиторії й містить випадки для BE-003 … BE-008: активні й приховані фрази, порожні переклади різними мовами, усі шість категорій, латиську діакритику, кирилицю, емодзі, переноси рядків. Нова задача, якій потрібен новий випадок, додає його в сід.
- **Одноразово** для вже створеного Docker-volume: `docker compose down -v`, інакше `orakuls_test` не з'явиться (init-скрипти MySQL працюють лише при створенні volume). Робоча БД поки порожня, нічого не втрачається.

Розподіл: `run.php` — логіка без БД, `api.php` — ендпоінти на відомих даних, `smoke.php` — запущений сервер (локально або хостинг), лише читання.

Наскрізний прогін фронта проти бекенда — BE-010.
